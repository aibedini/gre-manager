# راهنمای کامل نصب و راه‌اندازی Multi-GRE Tunnel Manager

این راهنما شما را **قدم‌به‌قدم** از صفر تا اتصال کامل می‌برد: اول یک سرور خارج با یک سرور ایران، بعد چند ایران، و در انتها اتصال یک ایران به چند خارج (نسخهٔ ۲).

> در تمام مثال‌ها از این IPهای فرضی استفاده می‌کنیم — با IPهای خودتان جایگزین کنید:
>
> | سرور | IP فرضی در این راهنما |
> |---|---|
> | خارج ۱ | `1.2.3.4` |
> | خارج ۲ | `9.9.9.9` |
> | ایران ۱ | `5.6.7.8` |
> | ایران ۲ | `5.6.7.9` |

## ۱. پیش‌نیازها و چک‌لیست قبل از شروع

**روی هر دو سرور:**

- سیستم‌عامل: اوبونتو/دبیان (یا RHEL-like) با systemd
- دسترسی root (یا `sudo`)
- اتصال اینترنت
- دیتاسنتر ایران اجازهٔ عبور **پروتکل GRE (شمارهٔ ۴۷)** را بدهد — اکثر دیتاسنترهای معروف ایران می‌دهند؛ اگر تونل بالا نیامد، اولین مشکوک همین است

**این اطلاعات را از قبل آماده کنید:**

- [ ] IP عمومی سرور خارج: `____`
- [ ] IP عمومی هر سرور ایران: `____`
- [ ] پورت‌هایی که سرویس‌تان (مثلاً Xray) روی خارج به آن‌ها گوش می‌دهد: مثلاً `443` و `8443`
- [ ] پاسخ این سؤال: «چند دقیقه قطعی برایم قابل قبول است؟» (پیش‌فرض: ۲ دقیقه)

**معماری نهایی این راهنما:**

```
ایران ۱ (5.6.7.8) ──gre-ir01──► خارج ۱ (1.2.3.4) ──► Xray روی 0.0.0.0
ایران ۲ (5.6.7.9) ──gre-ir02──► خارج ۱ (1.2.3.4)
```

کاربران به IP ایران وصل می‌شوند؛ ترافیک پورت‌های انتخابی از تونل به خارج می‌رسد.

## ۲. مرحلهٔ ۱ — نصب روی همهٔ سرورها

این دستور را **روی سرور خارج و روی تک‌تک سرورهای ایران** اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/aibedini/gre-manager/main/install.sh | sudo bash
```

خروجی موفق:

```
  Multi-GRE Tunnel Manager — installer
  github.com/aibedini/gre-manager

  Checking dependencies        [################################] 25%
  Downloading gre-manager      [################################] 55%
  Verifying SHA-256 checksum   [################################] 75%
  Installing gre command       [################################] 100%

  [+] gre-manager v2.1.0 installed -> /usr/local/sbin/gre
```

از این لحظه روی هر سرور فقط کافی است بنویسید:

```bash
sudo gre
```

> نصب‌کننده آخرین نسخهٔ رسمی را با **تأیید checksum** نصب می‌کند؛ یعنی فایل دست‌نخورده از ریلیز گیت‌هاب می‌آید.

## ۳. مرحلهٔ ۲ — راه‌اندازی سرور خارج

روی **سرور خارج**:

```bash
sudo gre
```

منو را می‌بینید. روی سرور تازه یک خط راهنما هم می‌بینید: `Start here → this server is in IRAN? press 1 · is it the FOREIGN server? press 2` — یعنی **سرور ایران = گزینهٔ 1، سرور خارج = گزینهٔ 2**.

چون این سرور **خارج** است، گزینهٔ **`2`** را بزنید (Configure this server as FOREIGN / add an Iran node).

### ۳.۱ — سؤال‌های اولین اجرا (فقط بار اول پرسیده می‌شود)

```
[*] FOREIGN server setup (first run)
Public IP of THIS foreign server [1.2.3.4]:
```

IP را خودش تشخیص می‌دهد؛ Enter بزنید (اگر اشتباه بود، IP درست را تایپ کنید).

```
Restrict GRE (proto 47) to known Iran node IPs? (recommended) [Y/n]:
```

**Enter (بله)** — با این کار فقط IP سرورهای ایرانِ شما اجازهٔ اتصال GRE به این سرور را دارند.

> اگر روی این سرور از قبل تونل GRE دیگری (مال ابزار دیگر) وجود داشته باشد، قبل از این سؤال هشدار می‌گیرید که آن تونل‌ها بلاک می‌شوند — در آن صورت یا whitelist را رد کنید یا اول وضعیت آن تونل‌ها را مشخص کنید.

```
Drop inbound ICMP (ping) on this server? (tunnel subnets stay pingable) [y/N]:
```

اختیاری. اگر `y` بزنید سرور به پینگ عادی جواب نمی‌دهد (کمتر لو می‌رود) ولی پینگ داخل تونل همچنان کار می‌کند.

```
[*] Auto-heal watchdog
[*] If a tunnel dies, the watchdog revives it automatically.
[*] How many minutes of tunnel downtime are acceptable for you? (0 = disable auto-heal)
Downtime tolerance in minutes [2]:
```

عدد تحمل قطعی را بزنید؛ مثلاً `2`. واچداگ هر ۱ دقیقه تونل‌ها را چک و تونل مرده را خودکار بالا می‌آورد. با `0` غیرفعال می‌شود. **بعداً هر وقت خواستید از منو گزینهٔ 7 می‌توانید تغییرش دهید یا خاموشش کنید.**

### ۳.۲ — ثبت سرور ایران اول

بلافاصله ادامه می‌دهد. اول لیست نودهای فعلی را نشان می‌دهد (بار اول خالی است) و بعد سؤال‌ها را می‌پرسد:

```
[*] Current Iran nodes on this FOREIGN:
  (none yet — this will be the first node)

[*] Add a new IRAN node
Node name (e.g. ir01) [ir01]:                     ← Enter
Public IP of the Iran server: 5.6.7.8             ← IP ایران ۱
Tunnel index (1-254) [1]:                         ← Enter
GRE key [1001]:                                   ← Enter
```

> از این به بعد هر بار که گزینهٔ ۲ را بزنید، **قبل از سؤال‌ها لیست همهٔ نودهای موجود را می‌بینید** — همیشه اول چک کنید نود قبلی ثبت شده یا نه.

خروجی موفق — **این بلوک را کپی کنید و نگه دارید، مرحلهٔ بعد لازم است:**

```
[+] Node 'ir01' added on FOREIGN.
------------------------------------------------------------
  Run 'gre' -> option 1 on the IRAN server and enter:
    Public IP of THIS Iran server : 5.6.7.8
    Public IP of the FOREIGN server: 1.2.3.4
    Node name                     : ir01
    Tunnel index                  : 1
    GRE key                       : 1001
------------------------------------------------------------
```

✅ کار سرور خارج فعلاً تمام است (به جز اضافه کردن ایران‌های بعدی که جلوتر می‌آید).

## ۴. مرحلهٔ ۳ — راه‌اندازی سرور ایران

روی **سرور ایران ۱**:

```bash
sudo gre
```

گزینهٔ **`1`** را بزنید (Configure this server as IRAN) و با مقادیر بلوک مرحلهٔ قبل جواب دهید:

```
[*] IRAN node setup
Public IP of THIS Iran server [5.6.7.8]:          ← Enter (خودش تشخیص داده)
Public IP of the FOREIGN server: 1.2.3.4          ← IP خارج
Node name [ir01]:                                 ← Enter (باید با خارج یکی باشد)
Tunnel index (1-254) [1]:                         ← Enter (باید با خارج یکی باشد)
GRE key [1001]:                                   ← Enter (باید با خارج یکی باشد)
Public (WAN) interface [eth0]:                    ← Enter (خودش تشخیص داده)
```

> **دربارهٔ نام نود/peer:** از نظر فنی لینک با «IP خارج + subnet base + index + key» برقرار می‌شود، نه اسم؛ ولی **توصیه می‌کنیم دو طرف یک اسم بگذارید** تا توی لاگ و status ردیابی راحت باشد. برای چک کردن لینک هر تونل، `sudo gre status` روی هر دو سرور خط `pair:` یکسانی چاپ می‌کند — اگر این خط دو طرف یکی بود، دو سر درست به هم وصل‌اند.

حالا پورت‌هایی که می‌خواهید از روی IP ایران به خارج منتقل شوند:

```
TCP ports (e.g. 80,443,8443): 443,8443
UDP ports (e.g. 443,8443): 443
```

> این‌ها همان پورت‌هایی هستند که سرویس‌تان (مثلاً Xray) روی سرور خارج به آن‌ها گوش می‌دهد.
> **پورت 22 (SSH) را نزنید** — SSH سرور ایران از کار می‌افتد (اگر بزنید، برنامه با هشدار جدی تأیید می‌خواهد).

```
Enable TCP MSS clamping on the tunnel? (recommended) [Y/n]:   ← Enter (بله)
Downtime tolerance in minutes [2]:                            ← مثلاً 2
```

خروجی موفق:

```
[+] Tunnel gre-ir01 is up (10.200.1.2/30, key 1001)
[+] TCP ports 443,8443 on 5.6.7.8 -> 10.200.1.1 (DNAT)
[+] UDP ports 443 on 5.6.7.8 -> 10.200.1.1 (DNAT)
[+] TCP MSS clamping enabled on gre-ir01
[+] systemd service 'multi-gre.service' installed and enabled (survives reboot)
[+] Watchdog enabled (checks every 1 min, downtime tolerance ~2 min)
[+] IRAN node 'ir01' configured.
```

## ۵. مرحلهٔ ۴ — تست اتصال

**روی سرور ایران:**

```bash
ping -c 3 10.200.1.1
```

**روی سرور خارج:**

```bash
ping -c 3 10.200.1.2
```

هر دو باید جواب بدهند. بعد، تست جامع:

```bash
sudo gre doctor
```

همهٔ چک‌ها باید `PASS` باشند. وضعیت کامل را هم می‌توانید ببینید:

```bash
sudo gre status          # یا sudo gre status --json برای مانیتورینگ
```

در خروجی status، زیر هر peer/nod یک خط **اثر انگشت جفت** می‌بینید که روی هر دو سرور دقیقاً یکسان است — با مقایسهٔ آن مطمئن می‌شوید دو سر تونل درست به هم وصل‌اند:

```
  - ir01: foreign 1.2.3.4, subnet 10.200.1.0/30, tunnel gre-ir01, tcp [443], udp [443], reachable
    pair: 5.6.7.8 <-> 1.2.3.4 · 10.200.1.0/30 · key 1001
```

**تست واقعی سرویس:** اگر Xray روی خارج روی پورت 443 گوش می‌دهد، حالا کانفیگ کلاینت را روی IP **ایران** (`5.6.7.8`) و پورت 443 بزنید — باید وصل شود.

> اگر پینگ رفت ولی سرویس کار نکرد: مطمئن شوید سرویس روی خارج روی `0.0.0.0` گوش می‌دهد (نه فقط `127.0.0.1`) و پورتش همان است که forward کردید.

## ۶. مرحلهٔ ۵ — اضافه کردن ایران‌های بیشتر

برای هر سرور ایران جدید، فقط دو کار لازم است:

**الف) روی سرور خارج** — `sudo gre` → گزینهٔ **`2`**:

```
Node name (e.g. ir01) [ir01]: ir02                ← نام جدید
Public IP of the Iran server: 5.6.7.9             ← IP ایران ۲
Tunnel index (1-254) [2]:                         ← خودش شمارهٔ آزاد بعدی را پیشنهاد می‌دهد
GRE key [1002]:                                   ← Enter
```

**ب) روی سرور ایران ۲** — نصب (مرحلهٔ ۱) و بعد `sudo gre` → گزینهٔ **`1`** با مقادیر جدید (`ir02`، index `2`، key `1002`).

ساب‌نت‌ها خودکار مجزا می‌شوند:

| نود | تونل | سمت خارج | سمت ایران | key |
|---|---|---|---|---|
| ir01 | `gre-ir01` | `10.200.1.1` | `10.200.1.2` | 1001 |
| ir02 | `gre-ir02` | `10.200.2.1` | `10.200.2.2` | 1002 |
| ir03 | `gre-ir03` | `10.200.3.1` | `10.200.3.2` | 1003 |

> حذف یک ایران: روی خارج گزینهٔ **`3`** (تونل + rule + کانفیگ همان نود پاک می‌شود) و روی خود سرور ایران گزینهٔ **`12`** (Uninstall).

## ۷. مرحلهٔ ۶ — وصل کردن یک ایران به خارج دوم (v2)

از نسخهٔ ۲، یک سرور ایران می‌تواند **هم‌زمان** به چند خارج وصل باشد:

```
                    ┌──► خارج ۱ (1.2.3.4)   پورت 443
ایران ۱ (5.6.7.8) ──┤
                    └──► خارج ۲ (9.9.9.9)   پورت 8443
```

> **قانون مهم:** هر پورت فقط به **یک** خارج تعلق دارد. نمی‌توانید پورت 443 را هم‌زمان به هر دو خارج بدهید (برنامه با ذکر نام peer متداخل جلویش را می‌گیرد). پورت‌های مختلف را بین خارج‌ها تقسیم کنید. (Failover خودکار یک پورت مشترک در نسخه‌های بعدی می‌آید.)

**ترتیب کار:**

**الف) روی خارج ۲** (`9.9.9.9`) — نصب + `sudo gre` → گزینهٔ **`2`**:

```
Public IP of THIS foreign server [9.9.9.9]:       ← Enter
... (سؤال‌های اولین اجرا) ...
Node name (e.g. ir01) [ir01]: ir01                ← نام نود روی این خارج
Public IP of the Iran server: 5.6.7.8             ← IP همان ایران ۱
Tunnel index (1-254) [1]:                         ← Enter
GRE key [1001]:                                   ← Enter
```

خارج ۲ یک دستور آماده چاپ می‌کند شبیه:

```
gre iran peer add --name nl1 --foreign-ip 9.9.9.9 --iran-ip 5.6.7.8 \
    --subnet-base 10.201 --idx 1 --key 1001
```

**ب) روی ایران ۱** — همان دستور آماده را اجرا کنید (یا منو → گزینهٔ **`1`** → Add):

```bash
sudo gre iran peer add --name nl1 --foreign-ip 9.9.9.9 --iran-ip 5.6.7.8 \
    --subnet-base 10.201 --idx 1 --key 1001 --tcp-ports 8443 --yes
```

> `--subnet-base` باید با peer اول متفاوت باشد (مثلاً peer اول `10.200`، دومی `10.201`) — خودش هم پیشنهاد می‌دهد. نام peer (`nl1`) روی ایران آزاد است، ولی IP خارج، base، index و key باید با خارج ۲ یکی باشند.
> توجه: `--tcp-ports` این peer نباید با پورت‌های peer اول تداخل داشته باشد.

**ج) تست:**

```bash
sudo gre iran peer list        # هر دو peer با وضعیت reachability
ping -c 3 10.201.1.1           # از ایران به خارج ۲
sudo gre doctor                # همهٔ peerها جداگانه چک می‌شوند
```

حالا: پورت `443` ایران → خارج ۱، پورت `8443` ایران → خارج ۲.

**حذف یک خارج از روی ایران:**

```bash
sudo gre iran peer remove --name nl1        # فقط همان peer پاک می‌شود، بقیه دست نمی‌خورند
```

## ۸. مدیریت روزمره

| کار | دستور |
|---|---|
| دیدن منو | `sudo gre` |
| وضعیت کامل + پینگ زنده | `sudo gre status` |
| وضعیت ماشین‌خوان (مانیتورینگ) | `sudo gre status --json` |
| چک سلامت (برای cron/هشدار) | `sudo gre doctor` (خروجی غیرصفر = مشکل) |
| تنظیم واچداگ | `sudo gre watchdog status` / `interval N` / `disable` / `enable` |
| لاگ واچداگ | `journalctl -t gre-watchdog` |
| ری‌استارت همهٔ تونل‌ها | منو → گزینهٔ `4` |
| بکاپ از کل تنظیمات | `sudo gre export` |
| برگرداندن بکاپ | `sudo gre import <file>` |
| آپدیت | `sudo gre update` (با تأیید checksum) |
| لاگ تغییرات | `cat /var/log/gre-manager.log` |

**بعد از reboot نیازی به هیچ کاری نیست** — سرویس `multi-gre.service` همه‌چیز را خودکار بالا می‌آورد.

## ۹. عیب‌یابی

| مشکل | علت محتمل | راه‌حل |
|---|---|---|
| تونل ساخته می‌شود ولی پینگ نمی‌رود | دیتاسنتر GRE (proto 47) را بلاک کرده | با `tcpdump -n proto 47` روی خارج تست کنید؛ اگر چیزی نرسید، با پشتیبانی دیتاسنتر صحبت کنید یا سرور ایران را عوض کنید |
| تونل فقط یک‌طرفه است (درخواست می‌رسد ولی جواب نمی‌رسد) | دیتاسنتر GRE را فقط یک جهت (مثلاً خروجی) فیلتر کرده | تست قطعی: روی ایران `tcpdump -n 'proto 47 and src host IP-خارج'` و روی خارج `tcpdump -n 'proto 47 and src host IP-ایران'` هم‌زمان با پینگ؛ هر جهت که صفر بود همان جهت بلاک است — راه‌حل: تیکت به دیتاسنتر یا تعویض سرور ایران |
| `gre doctor` می‌گوید DNAT missing | ruleها دستی پاک شده‌اند | منو → گزینهٔ `4` (Restart) |
| سایت‌ها نصفه باز می‌شوند | PMTU خراب | MSS clamp را فعال کنید (موقع setup سؤال می‌پرسد؛ پیش‌فرض بله) |
| SSH به ایران وصل نمی‌شود | پورت 22 را forward کرده‌اید | از کنسول دیتاسنتر: `sudo gre purge` و دوباره بدون پورت 22 راه‌اندازی کنید |
| واچداگ مدام تونل را ری‌است می‌کند | peer واقعاً down است یا ICMP داخل تونل بسته است | `journalctl -t gre-watchdog` را ببینید؛ سمت مقابل را چک کنید |
| بعد از آپدیت رفتار عجیب | کانفیگ قدیمی | مهاجرت خودکار انجام می‌شود و بکاپ در `/etc/multi-gre/iran.conf.v1.bak` است |
| `port overlap` هنگام peer add | همان پورت را به دو خارج داده‌اید | هر پورت فقط به یک خارج؛ پورت‌ها را تقسیم کنید |
| کانفیگ وصل می‌شود ولی IP خروجی اشتباه است (مثلاً ایران نشان می‌دهد) | مشکل از تونل نیست — outbound پیش‌فرض xray/پنل روی خارج ترافیک را به زنجیرهٔ دیگری می‌فرستد (بقایای reverse tunnel) | روی خارج، outbound آن inbound را `direct/freedom` کنید (routing rule) |
| تونل GRE دیگری روی همان سرور از کار افتاده | whitelist پروتکل GRE ما آن را بلاک کرده | `sudo gre doctor` را ببینید (WARN تونل unmanaged)؛ یا whitelist را خاموش کنید یا آن تونل را به gre-manager بسپارید |
| چک نهایی | — | خروجی `sudo gre doctor` و `sudo gre status --json` را نگه دارید |

## ۱۰. حذف و پاک‌سازی

سه سطح، بسته به اینکه چقدر عمیق می‌خواهید پاک کنید:

| سطح | روش | چه چیزی پاک می‌شود |
|---|---|---|
| **حذف یک نود/peer** | خارج: گزینهٔ `3` · ایران: `gre iran peer remove --name X` | فقط همان اتصال |
| **Uninstall** | منو → گزینهٔ `12` | هرچه gre-manager روی این سرور ساخته |
| **PURGE کامل** | `sudo gre purge` یا گزینهٔ `13` | **هر چه به GRE ربط دارد** — حتی تونل‌های دستی و بقایای ورژن‌های قدیمی و اسکریپت vatanhost |

> قبل از PURGE لیست کامل چیزهایی که پاک می‌شود نمایش داده می‌شود و تأیید می‌خواهد.

## دشبورد تحت وب (gre-hub)

برای مدیریت همهٔ سرورها از یک رابط وب (نقشهٔ تونل‌ها، وضعیت نودها، اکشن از راه دور، ترمینال SSH تحت مرورگر)، روی یکی از سرورها (ایران یا خارج — هر کدام که دسترسی به بقیه ازش راحت‌تر است) این را بزنید:

```bash
sudo gre hub install        # یا منو → گزینهٔ 14
```

این دستور همه‌چیز را خودکار انجام می‌دهد: نصب Node.js در صورت نبودن، دانلود پکیج هاب، `npm install`، ساخت و استارت سرویس `gre-hub.service`. بعدش:

```bash
# روی سیستم خودتان تونل SSH بزنید و مرورگر را باز کنید:
ssh -L 3939:127.0.0.1:3939 root@<server-ip>
# → http://127.0.0.1:3939
```

اولین بازدید پسورد هاب را می‌سازید؛ بعد در Settings حتماً **2FA** را فعال کنید. موقع اضافه کردن هر سرور، پسوردش را یک بار می‌دهید و هاب خودش یک SSH key اختصاصی می‌سازد و نصب می‌کند (پسورد نگه داشته نمی‌شود). مدیریت سرویس: `gre hub status|start|stop|restart|uninstall`.

### دسترسی تحت وب با دامنه (HTTPS رایگان)

اگر نمی‌خواهید از تونل SSH استفاده کنید و ساب‌دامینی دارید که به IP سرور اشاره می‌کند:

```bash
sudo gre hub domain hub.example.com
# یا منو → گزینهٔ 14 → گزینهٔ 5
```

این دستور خودش همه‌کار می‌کند: DNS را با IP سرور چک می‌کند (اگر اشاره نکند هشدار می‌دهد)، Caddy را نصب می‌کند، reverse proxy را می‌نویسد، گواهی Let's Encrypt را خودکار می‌گیرد و `HUB_SECURE=1` را فعال می‌کند (کوکی Secure + HSTS). بعدش دشبورد روی `https://hub.example.com` است. برگشت به حالت لوکال: `sudo gre hub unexpose`.

> نکته: برای صدور گواهی، پورت‌های 80 و 443 باید باز و آزاد باشند و رکورد A دامنه به IP سرور اشاره کند (CDN/پروکسی خاموش یا DNS-only).
